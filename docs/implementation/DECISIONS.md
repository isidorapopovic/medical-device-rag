# Architectural decisions

## Stage 01

- Preserve canonical JSON StateStore/SourceBuffer and their immutable revisions. Do not mirror assessments into SQLite. One `state/runtime.sqlite3` ledger is authoritative only for new run telemetry and budget reservations; existing JSON migrations/exports remain authoritative for findings. This follows Stage 01's permission to adapt existing persistence and avoids competing shadow state.
- New contracts live in `contracts.py`; legacy Finding and source IDs remain unchanged. Conversion is explicit and conservative. No inferred verified legal editions/profile facts.
- Central settings use installed Pydantic + dotenv (no pydantic-settings dependency). Only explicit known environment keys are loaded. Settings output is allowlisted; credentials never appear in dumps or validation errors emitted by adapters.
- Ollama is the only implemented production provider. Remote endpoints/cloud are blocked by default, with no cloud fallback. Cloud opt-in validates credentials but does not implement/enable an unsupported cloud client.
- Use SDK transport timeouts and cooperative cancellation/deadline checks between bounded calls; synchronous in-flight calls cannot be forcibly interrupted and finish within their configured transport timeout. A timeout never releases an attempt's reservation for reuse. Local generation also caps output tokens.
- Calls and retries share a run budget; conservative UTF-8 byte estimates bound unknown token usage. Missing usage remains explicitly estimated. Reservation occurs durably before IO; crashes leave reservations charged. Run IDs are random UUIDs, project correlation is hashed, stage names are allowlisted. Logs contain counts/codes only, never exceptions, model identifiers, paths, prompts or dossier text.

Stage 01 runtime details:
- One invocation-wide lazy run scope covers CLI, programmatic ask/index/extract/review/evaluate and nested provider/scorer operations. Context variables do not reset budget per retry. Native CPU scoring is charged as one bounded scorer operation (the scorer may internally use several mini-batches).
- Embeddings split the old 32-chunk caller batches under the prompt-character cap without truncating or reordering text. Individual overlarge inputs fail before IO.
- SDK HTTP phase timeouts and cancellation are cooperative, not OS-enforced process deadlines. Late results are withheld; no background inference thread is abandoned. Native CPU calls cannot be hard-interrupted. A future worker-process boundary would be required for a hard kill guarantee.
- Real SDK bound module helpers are replaced at call time by a configured, closed Client with local host, explicit timeout, no redirects and trust_env=false. Explicitly injected module callables preserve existing offline test seams. Direct historical ConnectionError propagation remains intact; CLI masks its body and ledger/logs use fixed codes.
- New contracts validate identifiers, normalized Unicode, UTC times, hashes, physical-page versus block locations and version/project/role references. Citation binding alone does not prove semantic relevance. Parent-text offset verification requires supplying the actual extracted block to Citation.verify; no parent text or authoritative edition is invented.
- Legacy assessment section failures remain `failed` to preserve JSON contracts and resume behavior. The new invocation ledger is `blocked` after an execution failure; source snapshots and findings are retained. New assessment contract statuses do not silently replace the legacy section vocabulary.
- JSON assessment persistence is adapted, not duplicated: existing StateStore migrations/roundtrip tests continue to govern legacy artifacts; new contracts roundtrip as validated JSON. SQLite schema versions 1 and 2 cover only new run/usage data. Moving source documents/registries/findings to SQL is deliberately deferred to their stages, never auto-imported.
- Partial usage counters are not assumed complete: a failed or unmetered attempt keeps its whole reservation. Input bytes plus a framing allowance are conservative estimates for Ollama, not tokenizer-verified bounds for every possible custom tokenizer. Prepared CPU pair counts are measured. USD is zero for implemented local operations; cloud client execution is unsupported.
- No heavyweight or new dependency is needed. No lint/type tool or corresponding project configuration is installed, so compile checks and pytest are the available checks. docs/ remains local and ignored per the user's existing policy; README and source/tests are tracked changes.

## Stage 02 decisions (2026-10-17)

- Canonical originals/extractions use immutable project-scoped JSON/content-addressed artifacts; the existing SQLite database remains run-usage only. No shadow assessment database, new SQL migration, index migration or legal fetch is introduced.
- Logical document UUID is derived from project/collection/normalized case-insensitive filename; document version increments on changed working bytes. Same-current-bytes re-upload is idempotent. Parser/OCR identity changes create a new extraction manifest for the same original revision, retaining the original creation timestamp. Original filenames are labels only; archive paths use hashes and generated IDs.
- UTF-8 and explicit BOM UTF-16 are supported with encoding diagnostics. Normalization preserves case/superscripts/line breaks, applies NFC, collapses horizontal whitespace and removes soft hyphens; per-character raw envelopes retain source-extraction provenance. Paragraph/table cells and Markdown section labels remain explicit. PDF table layout and omitted DOCX components are never represented as verified.
- File/archive validation is service-owned. The old save_uploaded_document helper remains a low-level non-overwriting byte writer for compatibility (existing tests use intentionally fake PDF bytes). It gains confined paths, size limits, serialized atomic writes and temp cleanup. Streamlit now uses ingest_uploaded_document for validated, revision-preserving publication.
- JSON heads publish only after durable original/manifest writes. A failed metadata publication can leave unreachable immutable blobs; originals are never garbage-collected automatically. A failed working-copy publication can leave a valid archived revision without a new live mirror; retry is idempotent. Concurrent same-category UI uploads are serialized with an exclusive lock.
- New SourceBuffer passages are schema 2 only when archive references exist; a serializer preserves exact legacy schema-1 shape and content-derived IDs. Legacy snapshots remain verification-limited and do not magically acquire original provenance. New source views bind project/document/version/file hash/span/page/offset and validate the original bytes.
- Indexing caches unchanged vectors by text/ID only with matching model/project metadata. --force-reembed supports deliberately changed mutable model weights. A complete staged candidate replaces the active collection only after embeddings and writes finish; the old collection is renamed as a recovery backup, not deleted. Promotion failure restores the previous name. In-memory BM25 cache clears after successful activation. Backup cleanup is manual and no actual user index was rebuilt during implementation.
- Collection promotion and the subsequent global index-manifest write are not an atomic cross-store transaction. Manifest writes are now atomic, but a publish failure still requires operator investigation/recovery using the retained backup. Concurrent index rebuild processes are not a distributed transaction. These limitations are explicit rather than presented as fully crash-atomic activation.
- OCR is explicit and local-only, default off, no downloads. PyMuPDF/Tesseract runs are shared-budget/cancellation/deadline guarded, with page/pixel caps; OCR output is visibly unverified. Missing/poor OCR yields needs_ocr. Native legal indexing does not silently adopt an archived OCR replacement. Real OCR engine integration is NOT RUN unless explicitly recorded.
- New ingestion events allow only generated run ID, hashed project, fixed stage/error vocabulary, counts and timing; no filenames, paths, source passages or exception bodies. Only explicit source-view output contains excerpts. Native parsing remains synchronous and resource-bounded, not a process-isolated hostile-document sandbox.

Additional Stage 02 compatibility and quality decisions:
- Logical names use NFC/Windows casefold comparison for routing, while copied filesystem paths are resolved without renaming user files. Ambiguous canonical names fail closed. Existing PDF-open injection/missing-file behavior is preserved through an explicit allow_missing resolver mode used only by extraction; manifest verification never enables it.
- Native pages dominated by Unicode replacement glyphs (over 5% of non-padding text by the current engineering heuristic) are marked unreadable/needs_ocr and produce no citable spans. This is a conservative extraction-quality rule, not calibrated legal confidence or proof of OCR accuracy.
- The initial full test run passed 445 tests with one optional model skip, but began before final glyph/filename refinements. It is not used as the final-code gate. A focused compatibility run then caught the resolver's interaction with the unchanged mocked PDF opener; the adapter was fixed, and the original test plus current ingestion cases passed unchanged.
- Older application versions do not understand new schema-2 archived source passages. Keep this reader (or export reports) when rolling code back after producing new reports; legacy schema-1 histories remain loadable and their IDs/shapes are preserved. No source archive is deleted by rollback.

## Stage 03 decisions (2026-10-17)

- Extend the existing DeviceAttribute/DeviceProfile contracts additively. The old fields/statuses and legacy adapter remain supported; new profiles include origin, review state, exact evidence IDs and source-backed conflict alternatives. No new dependency, SQLite shadow profile, legal registry, applicability rule or model download.
- Read explicitly selected archived device manifests, verify immutable originals, rank bounded passages across documents, then perform conservative literal extraction. Explicit per-passage product labels are mandatory for automatic facts; filenames/model subject assertions cannot establish product scope. Missing scope produces unknown/manual questions. This deliberately trades recall for competitor/multi-product separation and is not a semantic product-identification guarantee.
- Default extraction is deterministic and offline. Explicit --llm uses the existing local transport/run ledger with bounded calls, token estimates, output cap and deadlines. Invalid JSON gets one separate schema-repair request under the same run; no blind schema retry or raw exception echo. Unavailable providers/budgets preserve deterministic proposals and unknowns. Cancellation propagates.
- Exact quote/offset/project/version validation establishes provenance, not entailment. Copied values preserve negation/modal qualifiers; divergent literal values remain conflicting even if a human might consider them equivalent. OCR-derived spans are excluded rather than silently adopting unmeasured OCR facts. Risk class is never inferred; classification confidence is categorical.
- All source proposals are pending. High-impact fields require explicit reviewer confirmation/edit before downstream use. Every manual edit requires self-declared editor, reason, operation ID and expected revision; it carries manual origin and no misleading source support. Earlier evidence and conflict alternatives remain in immutable history. This is an audit trail, not authenticated signatures or external tamper-proof storage.
- One project-scoped current profile head publishes only after a durable immutable revision; request hash and review event live inside that revision. Exclusive locks and optimistic revision checks prevent lost updates. Identical operation retries are idempotent, conflicting reuse is rejected, and publication failure may leave unreachable immutable revisions without changing the head. No automatic cleanup. Idempotency lookup scans retained history and is intended for local MVP scale.
- Reviewed profiles cannot be replaced silently through extraction/import. Rejection of reviewed fields is the explicit prerequisite for replacement. There is one active product per project, rather than a new multi-product assessment workflow. Confirmed-only legacy projection changes assessment fingerprints when review changes; the existing unverified applicability behavior remains conservative.
- Explicit legacy import maps known aliases, preserves unmapped fields separately, preserves false versus null and marks all imported assertions unverified. Existing profile JSON is never rewritten automatically; no Stage 03 head means the legacy loader behaves as before. The sample now uses nulls instead of guessed market/boolean values.
- Streamlit editing belongs to the later UI stage per the Stage 03 specification. Native parsing limits, the Stage 02 poor-OCR limitation and index/manifest cross-store recovery limitations remain explicit; this increment does not claim to resolve them.

## Stage 04 decisions (2026-10-17)

- Add a separate project-scoped registry.sqlite3 with schema migration 1 for editions, requirements, coverage, registry revision and audit events. This implements Stage 04's persistent tables without changing the usage-only runtime ledger, canonical assessment JSON or immutable source archives. Payloads are immutable/hash-checked; new legal versions require new IDs. Approval transitions and import events commit atomically with optimistic revisions and idempotency keys.
- New Edition/Provision contracts extend the legal metadata requirements without silently reinterpreting Stage 01's minimal RegulationEdition/Requirement or old RequirementRecord. Exact legal quotes bind archived manifests, original hashes, native spans, offsets and physical pages. Hierarchy, legal source kind, effective dates, base/superseded editions, dependencies and evidence tags are explicit user metadata. Verification proves binding, not legal meaning/currentness.
- All newly imported records are proposed, including legacy draft conversion and records from exports carrying active flags. Human source verification, specialist review and activation are distinct recorded actions for each edition/provision. Coverage approval is a separate explicit human act. Reviewer labels and official-origin/rights attestations are self-declared; no authentication, professional qualification verification or automatic official-domain/legal verification is claimed.
- Distinguish binding original/consolidated/amending legal text from guidance, standards and synthetic fixtures. No source URLs are fetched. No normative legal seed or standards content is generated. Empty registry.example.json is the only shipped template. Standards cannot supply binding-law authority; export requires a recorded rights attestation as well as declared rights metadata.
- Select only active, effective, unexpired approved law/provisions with valid source originals and active dependencies. Reject overlapping active editions, conflicting wording for the same section/obligation key, cyclic/overlarge lineage and effective superseding amendments awaiting resolution. Distinct reviewed obligation keys support multiple duties in one section. Historical retired editions remain audit data, not current selectable law.
- Coverage is measured against an explicitly approved manual expected-path inventory, never the extracted/model clause list. Report partial registry coverage when incomplete/unreviewed; completeness is limited to that chosen section inventory and does not prove all MDR obligations. Counts and warnings retain drafts, omissions and amendment/currentness uncertainty.
- Add explicit registry-backed review flags; preserve ordinary draft review as clearly labelled research-only compatibility behavior. No-law authoritative selection/review is blocked before inference with legal_registry_not_ready. This deliberately preserves legacy tests/commands while removing any implication of trusted applicability from draft reports. The actual applicability engine remains Stage 05.
- Freeze registry revision, exact selected IDs, as-of date, coverage and content fingerprint into assessment scope. Current export revalidates that binding and refuses retired/changed/inactive rows before writing. Historical rendering is labelled non-current and cannot claim authority. Registry snapshots are coherent under SQLite locks; registry validation and later filesystem report publication are not one cross-store transaction, so output is a dated revision snapshot, not continuous certification.
- Isolate synthetic fixture-only registries; production CLI and review selection never enable fixture authority. Test-only selectors explicitly exercise adapters without inventing trusted real law. Legacy imports preserve their draft semantics. OCR-derived legal spans remain unapproved; no real OCR/model run or legal verification is implied.
- Local MVP limits: one selected legal edition per registry-backed assessment; cross-edition dependency composition and advanced applicability are deferred. No automatic active-approval renewal, deletion, garbage collection, network synchronization or indexes rebuilt. Re-review/replacement requires explicit lifecycle work and new immutable IDs where content changes. Original archives must be retained.
